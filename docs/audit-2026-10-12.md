# Wabbit TV audit: 2026-10-12

This audit was done by reading the code only. The Flutter SDK isn't installed on the audit machine, so `flutter analyze`, the tests and the app itself were never run. Three reviewers covered three areas: code and architecture, security/tests/build, and UI/UX. A sample of findings from each was checked again against the source.

**Overall:** The engineering underneath is solid. All database work runs off the UI thread. Network reads have size and time limits. Credentials stay out of SQLite and the logs. There are about 586 tests that check real behavior. The weak spots are the edges:

- the player's desktop conventions;
- a few data-cleanup and import bugs;
- the player skipping certificate checks on HTTPS streams;
- design tokens that only exist in a document.

Effort estimates assume someone who knows the codebase and has Flutter installed.

## Code correctness (remaining)

- **Medium:** In `m3u_connector.dart:104,305-306`, one bad line aborts the whole playlist. A malformed `%` in `#KODIPROP` makes `Uri.decodeComponent` throw, and the error is reported as "unreachable". Strict `utf8.decode` rejects Latin-1/Windows-1252 playlists and reports them as "empty". **Fix:** try/catch per directive, and decode with `allowMalformed: true` or fall back to latin1.
- **Medium:** In `source_catalog_database.dart:5681-5722`, migrations v1–v3 run without a transaction. A crash in the middle leaves "table already exists" on every later open. v4–v10 don't re-read the version under the lock. This only works today because startup runs in a fixed order. **Fix:** wrap `_migrate` in one `BEGIN IMMEDIATE` and re-read the version inside it.
- **Medium:** `credential_store.dart:62` casts `decoded['serverUrl'] as String?`. A malformed stored value throws a `TypeError`, but only `FormatException` is caught.
- **Low-Med:** `source_artwork.dart:175-176` passes both `cacheWidth` and `cacheHeight`, so posters are squashed before `BoxFit.cover`. **Fix:** pass one dimension only.
- **Low:** `app_shell.dart:1537` creates a new variant port on every build. With finding #3 above, a failed player keeps re-querying "other sources". **Fix:** use a `late final` field.
- **Low:** `library_group_manager.dart:459-465`: when a load fails, the load-more loop retries forever in a tight DB loop. **Fix:** break on failure.
- **Low:** Three lifecycle gaps:
  - The initial-import isolates have no `onError`/`onExit` (`source_catalog_database.dart:156,190`), so a crashed worker leaves the source pending forever.
  - `BEGIN IMMEDIATE` runs before `try`, so a busy timeout skips `db.close()` (e.g. `:2067`, `:2171`, `:4204`).
  - There is no window-close hook, so up to 10 s of watch progress is lost on exit.
- **Low:** `app_shell.dart:2724` `_DeferredDestination` is unreachable.

## Performance

- **Medium:** Every DB call (63 call sites, `source_catalog_database.dart:5670`) spawns an isolate, opens SQLite, runs migrations and closes it again. That happens for progress saves every 10 s, per-channel EPG writes, and a Home refresh of up to 27 sequential spawns after every playback start. Long refresh transactions can push UI writes past the 8 s busy timeout. **Fix:** one long-lived DB worker isolate with a persistent connection, migrating once at startup.
- **Medium:** In `source_catalog_database.dart:3615-3655,3730`, "All sources" browse applies the cursor and LIMIT outside a `ROW_NUMBER()` CTE. Every 100-row page sorts the entire kind, and `COUNT(DISTINCT)` runs on every load. The variant ranking never does anything because identities are always 1:1. **Fix:** drop the window function, move the cursor into WHERE, and add an index on `(kind, available, hidden, normalized_title, id)`.
- **Medium:** Timeline drag sends a remote seek on every frame (`player_screen.dart:1388-1392`). **Fix:** preview the position locally and seek once in `onChangeEnd`.
- **Low:** Xtream list responses are buffered up to 256 MiB as raw bytes, a String and a JSON tree all at once (`source_catalog_database.dart:19,675,2693`), which can reach several GB at peak. **Fix:** stream through `utf8.decoder.fuse(json.decoder)`.
- **Low:** The FNV-1a hash in `m3u_connector.dart:370-375` allocates a BigInt for every byte. Dart ints already wrap, so the BigInt isn't needed.

## Security & privacy (remaining)

- **Low:** Xtream over plain `http` is accepted silently, with the credentials in every query string (`source_setup_controller.dart:881-889`). **Fix:** show an "unencrypted connection" note.
- **Low:** The M3U URL check only blocks `file:`. `C:/…` (parsed as scheme `c`), `edl://`, `av://lavfi:` and `data:` all reach mpv (`m3u_connector.dart:351-359`, `playback_handoff.dart:390-394`). **Fix:** allow only http(s), rtmp(s), rtsp, rtp and udp, and pass a `protocolWhitelist` without `file`.
- **Low:** M3U stream URLs, which are often Xtream URLs with the credentials embedded, are stored in plain text in SQLite. The DB lives in **Roaming** AppData, so it syncs with roaming profiles (`source_catalog_database.dart:804-806`). **Fix:** move the DB to LocalAppData. PLAN.md:23 records this as a known trade-off.
- **Low:** Artwork fetches go to any host the provider names, including loopback and LAN addresses, and start after a 160 ms focus dwell (`artwork_loader.dart:76-82`). The README's claim that the app "only contacts a source explicitly configured by the user" is false. **Fix:** reject private and loopback IP literals, and correct the README.
- **Checked and clean:** no TLS bypass in `dart:io`, fully parameterized SQL, correct FTS5 quoting, no XML parsing, artwork cache file names hashed with SHA-256, no logging of credentials, and the probes are compile-time gated.

## UI/UX (remaining)

**Design system:**
- **Medium:** There is no token file. 165 hex literals are spread across 17 files, and some have drifted:
  - `_raised` is `#252624` in `multiview_screen.dart:10` and `pip_overlay.dart:8`, against `#222321` in DESIGN.md.
  - There are two error reds (`#FFC1B3` and `#FF8D83`), and DESIGN.md has no error token.
  - `#1D1E1D` is off-palette (`guide_screen.dart:2647`).

  **Fix:** one `quiet_broadcast.dart` file for colors, type roles and radii, plus button, dialog and snackbar themes in `ThemeData`.
- **Medium:** 58 of 240 `fontSize` literals are off the type scale. The two Home shelves don't match each other: pinned cards are 13/11 px (`home_screen.dart:1680,1693`) and recently watched cards are 18/13 px (`:2123,2132`). Some buttons are 11 px, below DESIGN.md's 12 px floor (`my_library_screen.dart:1219,1314`).
- **Low-Med:** There are three confirmation patterns: a stock `AlertDialog` with 28 px M3 corners, a custom one, and inline confirmations. There are also two notice styles: a stock light `SnackBar` at `app_shell.dart:557` and the player's graphite `_Notice`.
- **Low:** Focus causes layout shifts, which DESIGN.md forbids. Borders go from 1 px to 2 px at `home_screen.dart:2961,3115` and `player_screen.dart:1371,1457`. Home's animations also ignore reduced motion.

**Flows and states:**
- **Medium:** There's no Favorite or Organize action in the player. Organize during PiP forces "Stop playback?", which a single → press on a Browse row can trigger (`basic_browse_screen.dart:2737-2742`, `app_shell.dart:867-869`). Opening Settings also stops playback (`app_shell.dart:698`).
- **Medium:** Every playback failure shows the same "Playback is unavailable right now." (`player_screen.dart:1212-1217`). **Fix:** 3–4 typed messages (stream limit or auth, network, unsupported), each with a next step.
- **Medium:** Source refresh failures are generic, and "Last refresh complete." has no time on it (`source_management_screen.dart:1163,1848,1857`). Source setup's typed errors could be reused here.
- **Medium:** First-run and dead-end problems:
  - Browse's "Add source" goes to the Sources list, while Home goes straight to the add-source form (`app_shell.dart:2159` vs `:2045`).
  - Search has no "no sources" state (`local_search_screen.dart:847-853`).
  - When every source is disabled, Browse still says "Add a source" (`basic_browse_screen.dart:1387-1398`).
- **Medium:** No minimum window size is set (`windows/runner/main.cpp:29`). The player controls (~400 px) and the 420 px confirmation overflow in a small window, and window size and position aren't remembered. **Fix:** `windowManager.setMinimumSize(Size(800, 520))`.
- **Medium:** Mouse use:
  - Browse, Search, Guide and Library rows have no hover state and no click cursor.
  - One click on a Live row starts the stream.
  - The Organize icon target is about 32 px (`basic_browse_screen.dart:2767-2771,2847-2853`).
- **Low:** Import progress just says "Importing", with no count (`source_setup_screen.dart:1081-1087`), so a 50k import looks stalled.

**Accessibility:**
- **Medium:** Selection is shown by color alone:
  - The connector picker uses only fill (1.10:1), with no `selected` semantics (`source_setup_screen.dart:455-470`).
  - The stream-count choices use the amber focus edge to mark selection, so selected and focused look the same (`source_management_screen.dart:1546-1549`).
  - Multiview marks selection with 1 px amber and focus with 2 px amber (`multiview_screen.dart:295-296`).
- **Low:** Player buttons have both a `Tooltip` and a `Semantics` label, so screen readers announce them twice (`player_screen.dart:1519-1523`). Some icons are confusing: "Move corner" uses a flip-camera icon (`pip_overlay.dart:231`), and "Add channel" reuses the Guide icon.

## Tests

- **Strong overall:** 51 files and about 586 tests. They use real SQLite in temp directories and a loopback `HttpServer`, with hand-written fakes and no mocking framework. Migrations from v2, v3, v10 and v11 to v12 are covered, including concurrent opens.
- **Gaps:**
  - `SecureCredentialStore` has no tests.
  - `MediaKitPlaybackTransport` has no tests; all playback tests use a fake.
  - Nothing tests HTML, non-JSON, invalid-UTF-8 or oversized Xtream responses.
  - Nothing tests non-http M3U schemes, or credentials containing `/ ? # % @` or spaces.
  - `minimal_continuations.dart` (665 lines) is never imported by any test.
- **Timing-dependent tests:** these can pass without testing what they claim on slow CI:
  - fixed 250 ms lock holds (`epg_database_test.dart:59`, `phase5_data_foundation_test.dart:105`);
  - a 50 ms "nothing changed" wait (`m3u_source_lifecycle_test.dart:333`);
  - a real 10 s sleep (`xtream_refresh_adapter_test.dart:334`);
  - the 50k-row tests, which have 45 s timeouts.

## Build, dependencies, repo

- **No CI.** Add a `windows-latest` workflow that runs format check, `flutter analyze`, `flutter test` and `flutter build windows --release`, plus Dependabot.
- **Lints are defaults only.** Add `strict-casts`, `strict-inference`, `strict-raw-types`, `unawaited_futures`, `discarded_futures`, `avoid_dynamic_calls`, `cancel_subscriptions` and `close_sinks`. The code already uses `unawaited` on purpose, so this should be cheap.
- **Dependency updates:** sqlite3 3.5.1 → 3.7.0 and flutter_secure_storage 11.0 → 11.2. media_kit hasn't been released in about 10 months, and `media_kit_libs_windows_video` downloads a libmpv/FFmpeg build dated **2023-09-24** (mbedTLS backend) that parses untrusted streams, so check that FFmpeg version against known CVEs.
- **Flutter 3.47 Material split:** the old `material` libraries are expected to be deprecated around Nov 2026, so plan the move to `material_ui`.
- **Release identity:** the version is 1.0.0+1, with no MSIX, installer or code signing. `CompanyName`/`ProductName` in `windows/runner/Runner.rc:92-98` decide the AppData folder for both the DB and secure storage. Lock them in before the first release, because changing them later strands users' data.
- **Repo size:** about 29 MB of mock PNGs in `.impeccable/mocks` and 2.6 MB in `docs/evidence`. Consider Git LFS.
- **.gitignore:** add `*.sqlite*`, `*.db`, `*.m3u`, `*.m3u8` and `.env*`. PLAN.md:23 says credential-bearing playlists must stay out of git, but nothing enforces it.
- **README is stale:** it says M3U URL and local-file sources are "later work", but both are implemented. The privacy claim is also wrong (see Security).

## Architecture

- **`source_catalog_database.dart` (6.1k lines) is five modules in one file:**
  - import and refresh workers plus the Xtream HTTP client;
  - a 66-call isolate facade;
  - the EPG store;
  - the personal-library store;
  - schema and migrations.

  **Split:** `catalog_schema.dart`, `import_workers.dart`, `xtream_client.dart`, and per-domain repositories behind one DB worker (see Performance).
- **Duplicated code that has drifted:**
  - Xtream endpoint building exists 5 times, with different `player_api.php` handling.
  - `_getJson`/`_refreshJson` are near copies.
  - `_writeStage`/`_upsertStage` have diverged; that causes Fix-first #6.
  - The visibility SQL predicate is pasted 13 times. A `visible_catalog` VIEW would remove that.
  - Color constants are defined in 44 places.
- **`_WabbitShellState` (~1.7k lines, ~40 fields)** mixes navigation, startup, overlays and PiP/multiview. **Highest-value refactor:** a `PlaybackPresentationController` that only the playback layer listens to. It fixes #3 and the variant-port churn together.
- **Test seams in production code:**
  - `_connectTestSeam`/`SourceSetupPort` is a second import path, and tests run it instead of the real worker.
  - There are scattered `*ForTest` flags.
  - `WabbitShell` takes about 25 injected parameters.
- **Schema debt:** `watch_state` only uses `last_played_at`, and its other columns duplicate `playback_progress`. The library_items/members/variant-ranking structure supports merges that never happen.

## Notably good

- All SQLite work runs off the UI isolate. Multi-step writes use `BEGIN IMMEDIATE` with rollback. Refresh is atomic and generation-guarded, so the last good catalog stays visible, and the app recovers after a crash.
- Hostile input is bounded everywhere: byte caps, deadlines and cancellation on every network read, plus a capped artwork cache and a limited decode size.
- Credentials: Xtream rows store only `{providerId, kind, extension}`. Secrets are read only at play or refresh time, worker errors are discarded, and `toString` output is redacted.
- Behavior layer:
  - the rail's reserved focus border means nothing shifts;
  - focus is restored on Back;
  - lists are virtualized with a fixed `itemExtent`;
  - artwork loads are capped and wait for a settle;
  - search has a 180 ms debounce;
  - the "showing saved catalog" degraded state works;
  - the Guide stays tunable when the schedule is missing.
- Async hygiene: consistent `mounted` and generation checks, timers cancelled in dispose, and a serialized PlaybackManager that flushes progress on stop.
